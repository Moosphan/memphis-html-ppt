# PPT UI 风格走查方案 (UI Audit Protocol)

> 本方案用于严格审查每一张 SVG 设计稿和 HTML 还原质量。
> 审查由独立 subagent 执行，设计者无法跳过或自审通过。
> 审查标准参考：Apple Keynote 模板、McKinsey/Bain 咨询 PPT、高端 pitch deck。

---

## 一、审查流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  设计者   │────→│ 自检提交  │────→│ 审查Agent │────→│ 结果判定  │
│ (主Agent) │     │ (SVG/HTML)│     │ (SubAgent)│     │ PASS/FAIL│
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                       │                │                  │
                       │           独立审查,             FAIL →
                       │           不共享上下文          返回具体
                       │                                 问题清单
                       │                                     │
                       └─────────────────────────────────────┘
                                    修改后重新提交
```

### 规则

1. **独立性**: 审查 subagent 不共享设计者的对话上下文，只接收 SVG/HTML 文件 + 审查标准
2. **不可跳过**: 每张设计稿必须通过审查才能进入下一步
3. **逐项打分**: 每个检查项给出 PASS / FAIL / WARN，FAIL 必须附具体修改建议
4. **一票否决**: 标记为"一票否决"的检查项如果 FAIL，整体判定 FAIL
5. **量化评分**: 满分 100 分，≥ 85 分 PASS，70-84 分需修改后重审，< 70 分打回重做

## 二、审查维度与检查项

### 维度 A: 排版与字体 (Typography) — 权重 25%

| # | 检查项 | 标准 | 一票否决 |
|---|--------|------|----------|
| A1 | **标题字号** | ≥ 正文字号的 3 倍 | ✅ |
| A2 | **字体层次清晰度** | 6 级层次可辨识: 页面标题 > 区域标题 > 卡片标题 > 正文 > 辅助 > 标签 | ✅ |
| A3 | **Serif/Sans 配对** | 标题用衬线体(Georgia/宋体), 正文用无衬线体(Montserrat/黑体) | |
| A4 | **行间距** | 正文行距 1.5-1.8, 标题行距 1.0-1.2 | |
| A5 | **字间距** | 标题字间距 -0.03~-0.05em, 标签字间距 0.08-0.14em | |
| A6 | **行宽** | 正文每行 ≤ 60 字符 (约 30 个中文) | ✅ |
| A7 | **对齐方式** | 主体内容左对齐, 仅封面/结尾可居中 | |
| A8 | **文字可读性** | 所有文字在预期背景下对比度 ≥ 4.5:1 | ✅ |
| A9 | **标签文字** | 大写, ExtraBold, 字间距 ≥ 0.08em | |
| A10 | **中英文混排** | 中英文之间有 1/4 em 间距, 英文不压中文字框 | |

**A 维度评判要点:**
- 标题是否一眼就能抓住注意力？
- 正文是否舒适可读，不需要眯眼？
- 整体排版是否有"杂志感"而非"Word 文档感"？

---

### 维度 B: 布局与空间 (Layout & Spacing) — 权重 25%

| # | 检查项 | 标准 | 一票否决 |
|---|--------|------|----------|
| B1 | **安全边距** | 内容区域距画布边缘 ≥ 80px (5%) | ✅ |
| B2 | **卡片间距** | 相邻卡片间距 20-32px, 一致 | |
| B3 | **留白呼吸感** | 卡片内文字距卡片边缘 ≥ 32px | ✅ |
| B4 | **视觉焦点** | 每页有且只有 1 个明确的视觉锚点 | ✅ |
| B5 | **主从关系** | 主卡片面积 ≥ 辅助卡片的 1.5 倍 | |
| B6 | **对齐网格** | 所有卡片边缘对齐到隐含网格线 | |
| B7 | **非对称平衡** | 布局不追求镜像对称, 但视觉重量左右均衡 | |
| B8 | **信息密度** | 单页文字总量 ≤ 80 字 (中文) | ✅ |
| B9 | **元素间距一致性** | 同类元素间距在全页内保持一致 (±4px) | |
| B10 | **垂直节奏** | 各区域高度比例合理, 无头重脚轻或头轻脚重 | |

**B 维度评判要点:**
- 页面是否"透气"？还是塞满了内容？
- 眼睛是否自然被引导到最重要的信息？
- 有没有"空白恐惧症"（害怕留白所以塞满）？

---

### 维度 C: 色彩与对比 (Color & Contrast) — 权重 15%

| # | 检查项 | 标准 | 一票否决 |
|---|--------|------|----------|
| C1 | **主色限制** | 每页最多 1 种主色 + 1 种辅色 | ✅ |
| C2 | **色彩和谐** | 强调色之间不冲突, 整体协调 | |
| C3 | **对比度** | 文字与背景对比度 ≥ 4.5:1 (WCAG AA) | ✅ |
| C4 | **色彩功能** | 颜色有语义: 强调=暖色, 数据=冷色, 警告=红/橙 | |
| C5 | **色块面积** | 色块面积 ≤ 页面 15%, 不喧宾夺主 | |
| C6 | **深浅平衡** | 深色元素与浅色元素有节奏地交替 | |
| C7 | **底色统一** | 全 deck 底色一致 (#FFF8EE) | |
| C8 | **色盲友好** | 不依赖单一红绿区分信息 | |

**C 维度评判要点:**
- 颜色是用来引导注意力的，不是用来"好看"的
- 如果把页面转灰度，层次关系是否依然清晰？

---

### 维度 D: 卡片与组件 (Cards & Components) — 权重 15%

| # | 检查项 | 标准 | 一票否决 |
|---|--------|------|----------|
| D1 | **卡片视觉权重分级** | 存在 ≥ 3 种不同权重的卡片 (Hero/Primary/Subtle) | ✅ |
| D2 | **描边一致性** | 同级卡片描边粗细一致 (±1px) | |
| D3 | **硬阴影** | 阴影无模糊 (stdDeviation=0), 方向一致 (右下) | ✅ |
| D4 | **圆角一致性** | 同级卡片圆角一致: Hero=32, Primary=24, Subtle=16 | |
| D5 | **卡片内边距** | 文字距卡片边缘 ≥ 32px | |
| D6 | **标签/角标样式** | 圆角药丸形, 色块底+白字/深字, 一致 | |
| D7 | **分隔线** | 细线 (2-3px), 深色低透明度 (0.1-0.15), 不抢视觉 | |
| D8 | **图标使用** | 图标风格统一 (线条或填充, 不混用), 尺寸一致 | |

**D 维度评判要点:**
- 卡片是否有层次感？还是所有卡片看起来一样"重"？
- 描边、阴影、圆角是否形成统一的设计语言？

---

### 维度 E: 装饰与 Memphis 风格 (Decoration & Memphis Style) — 权重 10%

| # | 检查项 | 标准 | 一票否决 |
|---|--------|------|----------|
| E1 | **装饰位置** | 装饰元素在四角/边缘, 不侵入内容区 | ✅ |
| E2 | **装饰密度** | 每页装饰元素 3-6 个, 不多不少 | |
| E3 | **装饰类型** | 点阵 + 波浪线 + 几何形状, 三种组合 | |
| E4 | **装饰不抢焦** | 装饰的视觉权重 < 最弱的内容卡片 | ✅ |
| E5 | **装饰一致性** | 同类型装饰在全 deck 中尺寸/样式一致 | |
| E6 | **Memphis 特征** | 有圆点、锯齿、三角、波浪中的 ≥ 2 种 | |
| E7 | **色块背景圆** | 1-2 个, opacity 0.12-0.20, 放在角落 | |
| E8 | **装饰与内容关联** | 装饰的色彩呼应页面主色 (非独立随机色) | |

**E 维度评判要点:**
- 装饰是"设计的一部分"还是"贴上去的贴纸"？
- 去掉装饰后，页面是否依然完整？（装饰应该锦上添花，不是遮丑）

---

### 维度 F: 内容结构与信息设计 (Content & Information Design) — 权重 10%

| # | 检查项 | 标准 | 一票否决 |
|---|--------|------|----------|
| F1 | **单页单主题** | 每页只传达 1 个核心信息 | ✅ |
| F2 | **标题即结论** | 标题应是观点/结论, 不是主题/名词 | |
| F3 | **要点精简** | 要点 ≤ 4 个, 每个 ≤ 25 字 | |
| F4 | **数字突出** | 关键数字用大字号 + 强调色 | |
| F5 | **留白=重点** | 最重要的信息周围留白最多 | |
| F6 | **视觉层次** | 标题 > 副标题 > 要点 > 说明, 层次分明 | |
| F7 | **Section/Page 标记** | 左上角 Section Chip + 右下角 Page Counter 存在且一致 | |

**F 维度评判要点:**
- 如果观众只看 3 秒，能抓住这页的核心信息吗？
- 有没有"信息过载"——试图在一页里塞太多东西？

## 三、评分规则

### 评分公式

```
总分 = A×0.25 + B×0.25 + C×0.15 + D×0.15 + E×0.10 + F×0.10

每个维度得分 = (该维度 PASS 数 / 该维度总检查项数) × 100
```

### 判定标准

| 总分 | 判定 | 行动 |
|------|------|------|
| ≥ 85 | ✅ PASS | 进入下一步 |
| 70-84 | ⚠️ REVISE | 返回具体问题清单, 修改后重审 |
| < 70 | ❌ REJECT | 打回重做, 需要重新设计 |

### 一票否决规则

任何标记为"一票否决"的检查项如果 FAIL，无论总分多少，整体判定为 **REJECT**。

一票否决项清单：
- A1: 标题字号 ≥ 正文 3 倍
- A2: 字体层次清晰度
- A6: 行宽 ≤ 60 字符
- A8: 文字可读性对比度
- B1: 安全边距 ≥ 80px
- B3: 卡片内留白 ≥ 32px
- B4: 每页有且只有 1 个视觉焦点
- B8: 单页文字 ≤ 80 字
- C1: 每页最多 1 主色+1 辅色
- C3: 对比度 ≥ 4.5:1
- D1: 卡片权重分级 ≥ 3 种
- D3: 硬阴影无模糊
- E1: 装饰不侵入内容区
- E4: 装饰不抢焦点
- F1: 单页单主题

## 四、审查输出格式

审查 subagent 必须输出以下格式的审查报告：

```markdown
# UI 审查报告

## 基本信息
- 审查对象: [文件名]
- 审查时间: [时间]
- 整体判定: [PASS / REVISE / REJECT]
- 总分: [XX/100]

## 维度评分

| 维度 | 得分 | PASS | FAIL | WARN |
|------|------|------|------|------|
| A 排版字体 | XX/100 | X/X | X/X | X/X |
| B 布局空间 | XX/100 | X/X | X/X | X/X |
| C 色彩对比 | XX/100 | X/X | X/X | X/X |
| D 卡片组件 | XX/100 | X/X | X/X | X/X |
| E 装饰风格 | XX/100 | X/X | X/X | X/X |
| F 内容结构 | XX/100 | X/X | X/X | X/X |

## 一票否决项
- [ ] A1: 标题字号 — [PASS/FAIL] [说明]
- [ ] B4: 视觉焦点 — [PASS/FAIL] [说明]
- ...

## 问题清单 (仅 FAIL 项)

### [FAIL] [维度][编号] — [检查项名称]
- **现状**: [具体描述当前的问题]

- **修改建议**: [具体的修改方案]

## 亮点 (做得好的地方)

- [亮点 1]
- [亮点 2]
```

## 五、审查触发时机

| 阶段 | 审查对象 | 必须通过才能 |
|------|----------|-------------|
| SVG 设计阶段 | 每张 SVG 设计稿 | 进入 HTML 还原 |
| HTML 还原阶段 | 每个 HTML 模板 | 进入下一个模板 |
| Deck 生成阶段 | 完整 deck 输出 | 交付给用户 |
| 用户修改后 | 修改后的 deck | 重新交付 |

## 六、审查 Agent 调用方式

审查 agent 通过独立的 subagent 调用，确保与设计者上下文隔离：

```
调用参数:
- subagent_type: "claude"
- 文件: 待审查的 SVG 或 HTML
- 审查标准: 本文档 (03-ui-audit-protocol.md)
- 模板设计规范: 02-template-design-specs.md
- 输出: 审查报告 (按第四节格式)
```

审查 agent 的 system prompt 核心指令:
```
你是一位资深 PPT 设计审查专家，拥有 15 年以上的演示文稿设计经验。
你的审美标准极高，以 Apple Keynote、McKinsey 咨询报告、顶级 pitch deck 为基线。
你的职责是严格、公正、细致地审查每一张设计稿。

你的审查原则:
1. 宁可严格也不放水 — 放过一个问题是你的失职
2. 每个 FAIL 必须给出具体的修改建议 — 不允许只说"不行"而不给方案
3. 关注细节 — 字号差 2px、间距差 4px、描边粗 1px 都可能是问题
4. 整体感受同样重要 — 即使所有技术指标 PASS，整体感觉不对也要 WARN
5. 你是独立审查者 — 不受设计者的影响，只依据审查标准判断
```

## 七、常见 FAIL 模式 (反面案例)

### 7.1 排版类 FAIL

```
❌ 标题 32px, 正文 18px — 比例只有 1.8:1, 远不够
✅ 标题 72px, 正文 18px — 比例 4:1, 有冲击力

❌ 标题和正文都用 Montserrat — 层次感弱
✅ 标题 Georgia, 正文 Montserrat — 杂志感

❌ 每行 80 个字符 — 太长, 眼睛疲劳
✅ 每行 40-50 个字符 — 舒适阅读

❌ 所有文字居中 — 像网页不像 PPT
✅ 主体左对齐, 仅封面/结尾居中
```

### 7.2 布局类 FAIL

```
❌ 卡片紧贴画布边缘 — 没有呼吸空间
✅ 卡片距边缘 ≥ 80px

❌ 6 个卡片同等大小 — 没有主从关系
✅ 1 个大卡片 + 2 个中卡片 + 3 个小卡片

❌ 文字紧贴卡片边缘 — 内边距不足
✅ 文字距卡片边缘 ≥ 32px

❌ 每页塞 200+ 字 — 信息过载
✅ 每页 ≤ 80 字, 核心信息突出
```

### 7.3 色彩类 FAIL

```
❌ 5 种颜色均匀分布 — 花哨但没重点
✅ 1 种主色大面积 + 1 种辅色点缀

❌ 红色文字在白色背景 — 对比度只有 4.0:1
✅ 深色文字在浅色背景 — 对比度 ≥ 7:1

❌ 色块面积占页面 40% — 颜色喧宾夺主
✅ 色块面积 ≤ 15%, 用于强调
```

### 7.4 装饰类 FAIL

```
❌ 装饰圆点覆盖在文字上方 — 影响阅读
✅ 装饰在四角/边缘, 远离内容

❌ 每页 15 个装饰元素 — 像幼儿园
✅ 每页 3-6 个装饰元素, 点到为止

❌ 装饰颜色和页面主色无关 — 像随机生成
✅ 装饰颜色呼应页面主色
```
